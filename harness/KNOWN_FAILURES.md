## The recurring shape

**Thirteen fake guards** — tests structurally unable to fail — is the most repeated class.
(The count in this sentence had itself gone stale at six while the table above numbered them
to thirteen; corrected 2026-09-08.) Each survived a green suite and a review. The mechanical
answer is `evals/` (mutation testing) and `guard-auditor`; the cultural answer is
`CLAUDE.md`'s "a test that cannot fail is worse than no test". Second most repeated: **a
signal computed and never read** (halted folds, `annualisation_is_meaningful`,
`rows_removed_by` before consumers). Third: **one-sided bounds** on two-sided properties.

Fourth, and new on 2026-09-08, when the suite ran for the first time on a machine other than
the one that wrote it: **a test that could only ever pass in one place**. Two of those, plus
an agent brief and five systemd units, all with one root cause — an absolute path, or an
interpreter version, taken from the authoring environment and written down as though it were
a property of the project. The same mistake had been made about the network: a dozen
documents said every market-data host was unreachable, which was true of that sandbox and of
nowhere else, and it had been load-bearing enough to defer first contact to a VPS that was
never needed for it.

**The environment is not the project.** A claim about the first is the easiest kind to file
as a claim about the second, and this class is invisible to a green suite for the same
reason a fake guard is: on the machine where it was written, everything passes.
